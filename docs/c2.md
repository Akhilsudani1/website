Relationships

User → Checkout
One user can have many checkouts.

Asset → Checkout
One asset can have many checkout records.

CheckoutService → AssetService
CheckoutService uses AssetService to validate asset status.

AssetService → AssetRepository
AssetService depends on AssetRepository for persistence.

CheckoutService → CheckoutRepository
CheckoutService stores checkout history.

NotificationChannel ← EmailNotificationChannel
(Interface implementation)

NotificationChannel ← LogNotificationChannel
(Interface implementation)

Design Decisions
Inheritance
Used only for NotificationChannel interface
Allows swapping notification behavior (Email / Log)

Composition
Services contain repositories (not inherited)
Checkout contains references to User and Asset

Why Minimal Inheritance
Composition is preferred to keep low coupling
Business logic stays flexible and testable
